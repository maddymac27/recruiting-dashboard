## Phase Goal

**As a** job seeker running an active search, **I want to** manually log my cold outreach and see it in a filterable list with response tracking, **so that** I can tell which messaging converts.

**This plan (06-02) delivers the domain layer of the slice:** create + list + per-contact count over `outreach_messages`. After it, an outreach can be written and read back (proven by unit tests), which the Server Action (06-03) and page (06-04) build on.

<objective>
Create `src/domain/outreach.ts` with the three functions every later plan consumes — `createOutreach` (the shared DB writer, also reused by Phase 7), `listOutreach` (all rows or contact-scoped, joined to display names), and `getOutreachCountsByContact` (reduce-not-groupBy for the D-11 cross-link) — plus a unit test file proving OUT-01 storage, OUT-03 listing, and OUT-06 response round-trip.

Purpose: The domain module is the single write/read path the Server Action, the page, the demo seed, and the contact cross-link all call. Implements OUT-01 (log + store), OUT-03 (list), OUT-06 (responded/outcome), D-02 (dual-FK joins), D-11 (count aggregation).
Output: src/domain/outreach.ts + tests/domain/outreach.test.ts.
</objective>
