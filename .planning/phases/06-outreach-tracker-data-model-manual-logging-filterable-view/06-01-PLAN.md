## Phase Goal

**As a** job seeker running an active search, **I want to** manually log my cold outreach and see it in a filterable list with response tracking, **so that** I can tell which messaging converts — before any Gmail auto-capture is wired up.

*(Story derived from the ROADMAP Phase 6 Goal + its first-person success criteria; not invented.)*

**This plan (06-01) delivers the enabling backbone of that slice:** the `outreach_messages` data model plus the validated write contract, landed in both SQLite stores. It is the schema/migration foundation the first user-facing capability (06-02 domain, 06-03 form) depends on.

<objective>
Add the `outreach_messages` table to the Drizzle schema and its `newOutreachInput` zod write-contract, then generate one additive migration and apply it to BOTH the real and demo SQLite stores, verifying the table physically landed.

Purpose: Success criterion 1 requires the table to exist in both stores via one additive migration; every later plan (domain, Server Action, form, table, demo seed) writes/reads through this schema. Implements D-01 (additive table, both stores), D-02 (dual FKs), D-03 (forward-compat nullable sourceMessageId + source discriminator), D-04 (channel enum), D-05 (purpose plain text + Other), D-06 (subject nullable), D-07 (sentDate user-supplied, no default), D-08 (responded boolean + outcome free text).
Output: outreachMessages table + types, newOutreachInput schema, one generated migration, migrated data/real.sqlite and data/demo.sqlite, extended DB/validation tests.
</objective>
