## Color

Inherited verbatim — the natural-green şişe palette. No new hex values introduced; all Outreach-specific pills reuse the existing pastel Tailwind families already cataloged in `stage-pill.tsx` / `application-table.tsx`'s `AVATAR_COLORS`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f7f8fa` (`--background`) | Page background |
| Secondary (30%) | `#ffffff` (`--card`) | Cards, table surface, sidebar, dialog surface |
| Accent (10%) | `#3e9e5b` (`--primary`) | Reserved for: primary CTA buttons ("+ Log outreach" trigger, dialog "Save"), active nav link (`/outreach`), focus rings, the "Responded" pill (see below), avatar-name hover state |
| Destructive | `#ef4444` (`--destructive`) | Form validation/save-failure error text only — **not** used for "no response yet" (see rationale below) |

Accent reserved for: the "+ Log outreach" trigger button, the Dialog "Save" submit button, the `/outreach` active sidebar link, all focus rings (`focus:ring-2 focus:ring-ring/40`), and the "Responded = true" pill. Never used for neutral/pending states.

**New categorical pills for this phase — all reused from the existing pastel palette, no new hues:**

| Field | Value | Classes |
|-------|-------|---------|
| Channel | LinkedIn | `bg-blue-100 text-blue-700` (reused from Applied stage pill) |
| Channel | Email | `bg-cyan-100 text-cyan-700` (reused from avatar cyan) |
| Purpose | Referral ask | `bg-violet-100 text-violet-700` (reused from Screen stage pill) |
| Purpose | Intro request | `bg-amber-100 text-amber-800` (reused from Offer stage pill) |
| Purpose | Recruiter outreach | `bg-emerald-100 text-emerald-700` (reused from Interview stage pill) |
| Purpose | Coffee chat | `bg-rose-100 text-rose-700` (reused from Rejected stage pill hue, repurposed neutrally — not an error signal here) |
| Purpose | Follow-up | `bg-slate-100 text-slate-600` (reused from Saved stage pill) |
| Purpose | Other | `bg-zinc-100 text-zinc-600` (reused from Withdrawn stage pill — neutral catch-all) |
| Responded | true | `bg-emerald-100 text-emerald-700`, label "Responded" |
| Responded | false | `bg-secondary text-secondary-foreground`, label "No response yet" |

**Rationale — "No response yet" is NOT destructive-red:** unlike the board's "Gone quiet" badge (which fires only after a stage-appropriate silence *threshold*, an explicit auto-flag per DASH-03), Phase 6 has no staleness threshold for outreach (not a stated OUT-01..06 requirement). A freshly logged, not-yet-answered outreach is the normal/expected state, not a failure — so it renders as a neutral secondary pill, never destructive. Do not invent a red "no response" indicator this phase.

## Surface Contracts

### 1. `/outreach` — Outreach tab (list-collection)

- New sidebar nav link "Outreach" added to `NAV_ITEMS` in `nav-shell.tsx`, positioned after "Contact Database" (adjacent related surface) and before "Review". Active state: `bg-primary/10 text-primary`, identical to every other nav item — no new nav styling.
- Page header: Display-size h1 "Outreach" (28px/600/1.2) + Body-size description (16px/400/1.5): "Cold outreach you've sent — see what's working." Matches `contacts/page.tsx` header structure exactly.
- "+ Log outreach" trigger button sits to the right of (or directly under) the header, `variant="secondary"` sized like `QuickSaveDialog`'s trigger, OR `bg-primary` if treated as the page's primary action — **use `bg-primary text-primary-foreground hover:bg-primary/90`** since logging outreach is this page's single primary action (distinct from the sidebar's two capture buttons, which stay as-is).
- Table reuses the `application-table.tsx` "Excel-style" pattern exactly: search input (`h-9 w-64 rounded-md border border-border bg-card px-3 text-[14px]`) + two `<select>` filters (Channel: All/LinkedIn/Email; Responded: All/Responded/No response yet) + row count indicator (`{rows.length} of {total}`) + click-to-sort column headers (`ArrowUp`/`ArrowDown`/`ChevronsUpDown` from lucide-react) + bordered `rounded-xl border border-border bg-card` table wrapper + `hover:bg-muted/40` row hover.
- Columns (final set): **Recipient** (avatar + name, `avatarColor()` hash reused verbatim) · **Company** · **Channel** (pill) · **Purpose** (pill) · **Subject** (truncate, em-dash if null) · **Sent date** · **Responded** (pill) · **Outcome** (truncate, em-dash if null) · **Actions** ("View" ghost button, right-aligned).
- Sortable by: Company, Channel, Sent date (default sort, desc — "recency"), Responded. Filterable by: search (recipient/company/subject/outcome text), Channel select, Responded select — satisfies OUT-04 ("filter and sort by company, channel, and recency") plus D-09's Responded filter.
- Deep-link support: `/outreach?contactId={id}` pre-filters the table server-side to that contact and renders the dismissible "Filtered by {contact name} ✕" chip above the filter row (same visual weight as the search input row).

### 2. Logging form (Dialog) — `form` element

Mirrors `ContactConversationForm`'s Dialog structure and `max-h-[90vh] overflow-y-auto` sizing. Field order:

1. **Recipient** — `Select` with "+ New contact" (`NEW_CONTACT_VALUE` sentinel, reused pattern) or existing contact by name. If new contact selected, reveal a **trimmed** sub-form (deliberately smaller than `ContactConversationForm`'s full new-contact block, to keep outreach logging low-friction per D-12): **Name** (required, `Input`), **Email** (optional), **LinkedIn URL** (optional). Role/Relationship/Source/Channel fields are omitted here — those belong to the full contact-log flow, not fast outreach logging.
2. **Company** — `Input`, required, find-or-create resolution identical to `quickSaveAction`'s `companyName` pattern.
3. **Channel** — `Select`, required: LinkedIn / Email (D-04).
4. **Purpose** — `Select`, required: Referral ask / Intro request / Recruiter outreach / Coffee chat / Follow-up / **Other** (last option). Selecting "Other" reveals a free-text `Input` beneath it (D-05).
5. **Subject** — `Input`, optional. Disabled/hidden with placeholder text "No subject (LinkedIn)" when Channel = LinkedIn; enabled when Channel = Email (D-06).
6. **Body** — `Textarea`, required, `min-h-32` (matches the Notes field styling in `ContactConversationForm`).
7. **Sent date** — `Input type="date"`, required, defaults to today's date on dialog open (D-07).
8. **Responded** — new `Checkbox` (shadcn official, to be installed), unchecked by default.
9. **Outcome** — `Input` (or short `Textarea`), optional free text. **Progressive disclosure**: rendered only when Responded is checked (mirrors the existing `isNewContact` conditional-block pattern) — keeps the form clean when logging a fresh, unanswered outreach.

Submit gating: canSubmit requires Recipient resolution + Company + Channel + Purpose + Body + Sent date (Subject/Outcome always optional — OUT-06 does not require an outcome to exist before saving). Save button disabled state and inline error rendering (`text-[14px] leading-[1.5] font-normal text-destructive`) match existing forms verbatim.

### 3. Read-full-body — Dialog (not inline expand)

**Decision (D-14 resolved):** Dialog, not inline row expansion — the existing system has no inline-expand precedent anywhere (application-table, contacts-table, review queue all use Dialogs/dedicated viewers for "see more"), so a Dialog keeps this surface consistent.

- Trigger: "View" ghost button in the table's Actions column (see Surface 1).
- Dialog title: `{Recipient name} · {Company}`.
- Metadata row directly under the title: Channel pill · Purpose pill · Sent date · Responded pill — same pill components as the table.
- Subject line (if present) rendered as a labeled line above the body; omitted entirely (not "—") when null, since LinkedIn messages structurally have none.
- Body rendered with `whitespace-pre-wrap` inside the scrollable `max-h-[90vh] overflow-y-auto` DialogContent — no truncation, arbitrarily long pasted messages remain fully readable (same stored-XSS mitigation note as `ContactConversationForm`'s Notes field: persisted verbatim, rendered only as escaped JSX text).
- Outcome (if present) rendered as a final labeled line.
- No edit affordance in this dialog this phase (read-only) — editing an outreach entry is not an OUT-01..06 requirement.

### 4. Cross-link surface

**Direction A — Outreach row → contact:** the Recipient cell renders avatar + name in the same visual style as `contacts-table.tsx`'s Name cell, but **as plain text, not a hyperlink** — no `/contacts/[id]` detail route exists in the shipped codebase, and creating one is out of this phase's scope (not an OUT-01..06 requirement). Do not fabricate a dead link.

**Direction B — Contact → related outreach (the functional cross-link, D-11):** `contacts-table.tsx` gains one new column, **"Outreach"**, positioned after the existing "Touchpoints" column. Renders a count badge in the exact same style as the existing Touchpoints badge (`inline-flex min-w-6 items-center justify-center rounded-full bg-secondary px-2 py-0.5 text-[13px] font-medium text-secondary-foreground`), wrapped in a `Link` to `/outreach?contactId={id}` when count > 0 (plain, non-linked `text-muted-foreground` "—" when 0). This is the concrete, working cross-link — it has a real destination (Surface 1's deep-link support) rather than pointing at a page that doesn't exist.
