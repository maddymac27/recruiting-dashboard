## Phase Goal

**As a** job seeker running an active search, **I want to** manually log my cold outreach and read back any message in full, **so that** I can tell which messaging converts.

**This plan (06-03) delivers the write path and the two interactive dialogs of the slice:** the Server Action, the logging form, the read-body dialog, and the checkbox primitive. After it, an outreach can be logged and any row can be read in full — the page (06-04) then hosts and lists them.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-06 | Tampering | logOutreachAction provenance | high | mitigate | Action hardcodes source:"manual" and sourceMessageId:null; newOutreachInput (06-01) declares neither field, so a manual row can never masquerade as gmail-ingested. |
| T-06-07 | Tampering (stored XSS) | outreach-view-dialog / body render | medium | mitigate | body/subject/outcome persisted verbatim, rendered only as escaped JSX text (whitespace-pre-wrap); raw-HTML injection prop never used (mirrors ContactConversationForm Notes). |
| T-06-08 | Denial (silent data loss) | form submit failure | medium | mitigate | Fail-loud: typed failure -> inline text-destructive + toast.error; unexpected throw -> "Something went wrong. Try again."; entry never silently dropped. |
| T-06-09 | Tampering | company/contact name resolution | low | mitigate | resolveCompany/createContact use Drizzle parameterized queries; no raw SQL. |
