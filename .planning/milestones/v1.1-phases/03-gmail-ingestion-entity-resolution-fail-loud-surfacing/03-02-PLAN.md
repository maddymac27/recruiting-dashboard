<objective>
Close the CAP-03 read-path gap RESEARCH flagged as CRITICAL (Pitfall 1): `getMergedField`/`setOverride` have existed since Phase 1, but NO read path calls `getMergedField`, so a user's saved correction is stored yet never displayed. Wire `getMergedField` into `getApplicationDetail` for the six `OVERRIDABLE_FIELDS`, and add an integration test proving an override survives a simulated re-parse of the same application.

Vertical-slice value: after this plan a real user who corrects a field (via the existing override write path) actually sees that correction on the job detail view — a capability that does not exist in the app today — and it is provably re-sync-safe before real ingestion ships.

Purpose: Without this wiring CAP-03 is unverifiable even after ingestion lands (the detail page would show the parser's re-derived value). It is independent of Gmail, so it ships in Wave 1.
Output: merged read path in `src/domain/applications.ts`; CAP-03 test in `tests/domain/applications.test.ts`.
</objective>
