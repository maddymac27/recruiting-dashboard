<objective>
Establish the Phase 3 persistence foundation and vet+install its external packages. Extend the Phase-1 structural stub tables `review_queue` and `dead_letter` (D-15) with the discriminator/display columns the fail-loud queues need, add the net-new `sync_runs` (REL-03) and `ingested_messages` dedup-ledger (DATA-06 / D3-06) tables, mirror them in `src/db/validation.ts`, and generate one additive Drizzle migration. Vet and install `googleapis`, `mailparser`, `html-to-text` behind a blocking package-legitimacy checkpoint (two tripped the too-new heuristic — RESEARCH Package Legitimacy Audit).

Phase user story (derived from the ROADMAP Phase 3 Goal, which is a first-person outcome-shaped line — not invented): **As a** job seeker running an active search, **I want to** have my job-application email flow into the tracker for a known set of senders — matched to the right application or surfaced for my review, never silently dropped — **so that** the record stays accurate without me remembering to update it and I can tell at a glance whether ingestion is healthy.

Purpose: Every downstream Phase 3 plan writes to these tables and validates through these schemas; the migration cannot be retrofitted mid-phase. RESEARCH's central insight — routing discipline is the hard problem — depends on the `ingested_messages` ledger existing first.
Output: extended/new tables in `src/db/schema.ts`, new zod schemas in `src/db/validation.ts`, one new migration under `drizzle/`, three approved packages in `package.json`.
</objective>
