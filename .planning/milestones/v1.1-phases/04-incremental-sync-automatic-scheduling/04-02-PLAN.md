<objective>
Deliver the actual ING-07 + ROADMAP-criterion-3 behaviors. `runGmailSync` gains an optional `historyId` cursor: when present it fetches changed message ids via `fetchHistoryMessageIds`; on a Gaxios 404 (expired/invalid cursor) it falls back to the existing `lastSync`-windowed full-fetch bounded by the last successful run (D4-04), recording `usedFallback: true`; any non-404 error still fails loud. On success it re-seeds the cursor from `getProfileHistoryId()` after all work completes. `finishSyncRun` persists the cursor + fallback flag, `getLatestSuccessfulSyncRun` reads them back, and `syncGmailAction` threads the cursor both ways so the manual path is structurally identical to the scheduled path that 04-03 adds.

Purpose: This is the core of the phase — the incremental engine and its fail-loud expiry fallback. Everything downstream of the message-id source (per-message loop, Pass 2 label backfill, Pass 3 dead-letter reparse, dedup ledger) is reused verbatim.
Output: `runGmailSync` incremental + fallback + cursor-seed; persisted cursor; manual sync wired to it; parity/expiry/non-404/catch-up tests green.

MVP observable effect: a passing parity test (incremental == full dedup set), a passing cursor-expiry fallback test (usedFallback true), a passing non-404 fail-loud test, and a real success row in `sync_runs` carrying history_id + used_fallback.

Flagged assumption (spec-probe): the deterministic edge probe left ING-07 `unclassified/unresolved`; acceptance criteria are derived from ROADMAP criteria 2 and 3 and RESEARCH Pattern 1, not from an auto-shaped SPEC edge.
