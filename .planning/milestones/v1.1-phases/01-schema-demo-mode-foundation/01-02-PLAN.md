<objective>
Build the server-only Drizzle client singleton that resolves demo-vs-real once at startup, then prove the whole stack is wired end-to-end with one live page and one health route reading a real value from SQLite through Drizzle over the node:sqlite driver.

Purpose: This is the walking-skeleton liveness proof (SKELETON.md). It demonstrates Next.js + Drizzle + node:sqlite + the demo/real data-source swap all working together before any feature UI is built on them. It also establishes the structural demo/real separation (DEMO-02) that no later code path may violate.
Output: A single DB client module, a liveness page + health route, and a test proving the client cannot silently mix real and demo data.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| process env -> DB client | DASHBOARD_MODE selects which physical data file is opened |
| server modules -> browser bundle | The DB client / SQLite driver must never ship to the client tier |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-05 | Information Disclosure | real vs demo data mixing | high | mitigate | Path resolved once in one module from DASHBOARD_MODE; unset/invalid throws (Task 1); two physically separate files (DEMO-02, D-13) |
| T-01-06 | Information Disclosure | DB client in client bundle | medium | mitigate | `import 'server-only'` at the top of client.ts; page reads count in a server component / route handler only |
| T-01-07 | Tampering/Availability | duplicate SQLite handles on hot reload | low | mitigate | globalThis-cached singleton (RESEARCH §Demo/Real Data-Source Swap) |
| T-01-08 | Denial of Service | unset mode silently defaulting to wrong store | high | mitigate | Fail-loud assertMode throw, verified by the human checkpoint's unset-mode step |
</threat_model>
