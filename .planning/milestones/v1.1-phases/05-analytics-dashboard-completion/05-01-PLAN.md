## Phase Goal

**As a** job seeker running an active search, **I want to** open the dashboard and immediately see which applications have gone quiet or still need me to apply, **so that** I act on what matters without scanning the whole pipeline board.

_(Derived from ROADMAP Phase 5 goal + DASH-01/DASH-03 success criteria — not invented.)_

<objective>
Deliver the Today view — the new landing page at `/` that surfaces applications needing attention, judged by a per-stage staleness predicate (DASH-01), plus the derived "gone quiet" auto-flag over the accumulated status-event history (DASH-03). This plan builds the shared pure predicate (D5-08), composes the D5-01 activity clock, restructures routing so the pipeline board moves to `/board` (D5-04), and wires the two inline row actions (D5-05).

Purpose: This is the central vertical slice of the final phase — it answers "what needs me today," the first of the two questions Phase 5 exists to answer, and it is the only slice that touches routing.
Output: A working `/` Today view, `/board` pipeline board, a node-testable staleness module, a today read model, and an activated sidebar.

This plan adopts the three "confirm during planning" defaults as specified and research-supported: D5-06 (gone-quiet is a derived, non-destructive read-time overlay — never an auto-written event), and D5-08 (a new pure `application-staleness.ts` module mirroring the Phase 4 `staleness.ts` pattern).

No schema changes occur in this plan (RESEARCH: Phase 5 requires zero schema changes) — every column read (`applications.currentStageSince`, `conversations.occurredAt`) already exists.
</objective>
