## New Surfaces — Phase 5 Additions

### 1. Today View (`/`) — DASH-01, DASH-03

The new landing page. Server Component, same shell chrome as every other page (`<main>` padding, `<h1>` Display-size page title).

**Page title:** `<h1>` "Today" — Display (28px/600), identical styling to the existing Pipeline `<h1>`.

**Layout — two stacked sections**, each a vertical list of item rows (reuse `Card`/`CardContent`, not a table — matches the board's card-based visual language rather than the review-queue's table language, since these are richer action items, not audit rows):

**Section A — "Needs a follow-up"** (D5-01/D5-02 derived gone-quiet overlay: Applied ≥14d / Screen ≥10d / Interview ≥10d of no activity). Section heading: Heading (20px/600). Each row:
- Company name (Heading 20px/600) + role title (Body 16px/400) — same truncate-with-title-attribute pattern as `application-card.tsx`.
- Stage `Badge` (`variant="secondary"`, matching the existing job-detail stage badge convention — accent is never used on badges).
- A "gone quiet" indicator: small `Badge` in **Destructive** styling (`#DC2626`) with the warning icon, text **"Gone quiet · {N} days"** (N = days since the D5-01 activity clock). This is the one new use of Destructive this phase — see Color section below for the reserved-for extension.
- Two inline actions + click-through, per D5-05, left-aligned below the row content at `sm` (8px) gap:
  - **"Log a follow-up"** button (accent-filled, primary action of this row) — opens the existing `ContactConversationForm` (Phase 2 CAP-04) in a Dialog, pre-scoped to this application. Submitting resets the D5-01 clock, which removes the row from this section on next read.
  - **"Change stage"** button (outline/secondary styling, not accent — this row's one primary action is "Log a follow-up," not "Change stage," mirroring Phase 3's "one accent action per row" rule) — opens the existing `StageChangeDialog`.
  - The row's company/role text remains a `<Link href="/job/{id}">` (click-through to detail), same as `application-card.tsx`.

**Section B — "Not yet applied"** (D5-02: Saved stage, ≥7 days since save, a *separate*, non-"gone-quiet" nudge). Same row/Card layout as Section A, but:
- Indicator badge is **`variant="secondary"`** (muted, NOT Destructive) with copy **"Saved · {N} days ago"** — deliberately softer styling than Section A's Destructive badge, since D5-02 explicitly treats this as a different, lower-urgency category ("a nudge," not "gone quiet").
- Inline actions: **"Change stage"** (to Applied, once the user actually applies) + click-through. No "Log a follow-up" action here (nothing to follow up on for an application not yet sent).

**No snooze/dismiss control anywhere on this page** (D5-05, explicit exclusion) — rows clear only via the two inline actions or by editing the application from its detail page.

**Empty state (both sections empty):** Heading **"You're all caught up"**, body **"Nothing needs your attention right now — check back after your next sync."** (see Copywriting Contract).

**Empty state (one section empty, the other populated):** that section is omitted entirely (no "Nothing here" sub-heading per section) — only the whole-page empty state gets dedicated copy, keeping the page from feeling cluttered with two near-identical micro-empty-states stacked on top of real content.

### 2. Analytics View (`/analytics`) — DASH-06

Server Component page, `<h1>` "Analytics" (Display 28px/600).

**Layout — two stacked blocks:**

**Block A — Summary metrics row.** Visually identical grid pattern to the existing Phase 2 `KpiRow` (`grid grid-cols-2 gap-4 sm:grid-cols-4`, each metric a `rounded-lg border border-border bg-secondary px-4 py-3` tile, Label 14px/400 muted caption + Display 28px/600 numeral) — same component family, new metrics, not a new visual pattern:

| Metric | Label copy | Value |
|--------|------------|-------|
| Total applications | "Total applications" | count of all applications (any stage) |
| Response rate | "Response rate" | reached Screen+ ÷ applied, formatted as a percentage (e.g. "42%") |
| Active vs. closed | "Active" / "Closed" (two tiles) | count in non-terminal stages / count in terminal stages — mirrors the existing board KPI's "in progress"/"closed" split |
| Outcome breakdown | "Offers" / "Rejected" / "Ghosted" (three tiles, or one combined tile with three stacked numerals if space is tight — planner's call) | counts by terminal outcome |

**Block B — Funnel chart.** A `ChartContainer`-wrapped Recharts horizontal **Bar chart** (not a native Recharts `Funnel` shape — see Design System note above), one bar per stage in canonical order **Saved → Applied → Screen → Interview → Offer**, bar length = distinct-application "ever reached this stage" count (D5-07's definition). Monotonically non-increasing bar lengths read visually as a funnel without needing a custom SVG funnel shape.

- Chart heading: Heading (20px/600) — **"Applications by stage reached"**.
- Bar fill color: **Accent** (`#2563EB`) — this is the one chart element allowed to use accent (a data-visualization fill, not an interactive control; consistent with "never applied to... non-primary buttons" since a chart bar is neither).
- Axis/label text: Label (14px/400), `text-muted-foreground` — stage names on the category axis, counts as bar-end labels or via `ChartTooltip` on hover (planner's call; tooltip is the simpler default and matches shadcn's chart primitives out of the box).
- No color-per-stage (unlike the deferred 999.1 backlog's "per-stage column colors" idea) — a single accent fill keeps this "basic" per D5-07's explicit scope guardrail against ANLYT-01/02/03 richer-analytics creep.

**Empty state (zero applications exist at all):** Heading **"No data yet"**, body **"Analytics will populate once you start tracking applications."** — replaces both blocks entirely (no zero-value metric tiles or an empty chart frame).

**Time range:** all-time only, no date-range control this phase (D5-07) — no UI element should imply a filter exists (no disabled/greyed date picker either; simply absent).

### 3. Board Card — Gone-Quiet Overlay Badge (integration point)

`application-card.tsx` (Phase 2) gains one new optional visual element: when an application is flagged gone-quiet (same `src/lib/application-staleness.ts` predicate feeding the Today view, per D5-08's shared-module design), the card renders the identical small Destructive `Badge` ("Gone quiet · {N} days") used in Today View Section A, positioned top-right of the card content (`absolute` or a flex row with the company name — planner's call on exact placement, but it must not cover or truncate the company name, which already truncates against the card width). Cards for applications in Saved (not applied ≥7d) do **not** get a badge on the board — the softer "Saved · nudge" signal is Today-View-only, keeping the board's existing visual density unchanged for the common case.

## Color

Reused base tokens verbatim from `02-UI-SPEC.md`/`03-UI-SPEC.md`. This phase extends the **Destructive** reserved-for list beyond "failure signals" to include the new gone-quiet urgency signal, and adds the Accent chart-fill exception.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Page background, today-view/analytics card surfaces |
| Secondary (30%) | `#F4F4F5` (zinc-100) | Sidebar/nav background (unchanged), analytics summary tiles, "Saved · nudge" badge, stage `Badge`s on today-view rows |
| Accent (10%) | `#2563EB` (blue-600) | "Log a follow-up" button (today-view row primary action), active nav link (Today/Pipeline/Analytics), the funnel chart's single bar fill (data-viz exception — not an interactive control), focus rings |
| Destructive | `#DC2626` (red-600) | **Extended this phase**: the "Gone quiet · {N} days" badge (both Today View Section A and the board-card overlay) — in addition to its existing Phase 3 uses (sync failure line, dead-letter type badge, dead-letter count > 0) |

Accent reserved for: the elements listed above — never applied to body text, badges, or non-primary buttons ("Change stage" on both Today-view sections stays outline/secondary-styled, matching Phase 3's "one accent action per row" precedent).

Destructive reserved for: failure signals (unchanged Phase 3 uses) **plus** the gone-quiet urgency badge introduced this phase. Deliberately **not** extended to the "Saved · nudge" badge (Section B) — that stays neutral/secondary, since D5-02 explicitly treats it as a lower-urgency, different category from "gone quiet." No new semantic color (e.g. amber/warning) is introduced — the project holds to its existing 60/30/10 + one-destructive-accent system rather than adding a fourth semantic color for this phase's urgency signal.
