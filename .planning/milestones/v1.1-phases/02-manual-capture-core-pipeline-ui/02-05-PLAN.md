<objective>
Deliver the capture write slice layered on top of the read-only board: Quick-Save Job (CAP-01), Add Application / edit-any-field (CAP-02), and the explicit change-stage control (D2-06) — all routed through Server Actions that call event-sourcing-safe domain functions and revalidate the affected paths. After this slice the board is no longer read-only: a user can create and edit applications and move them between stages, and the board + KPI counts update live.

## Phase Goal (user story, derived from ROADMAP Phase 2 goal + success criteria)

**As an** active job-seeker, **I want to** quick-save a job I'm considering, manually add or edit any application field, and move an application to a new stage, **so that** my tracker stays accurate by my own hand — with every stage move preserved as dated history, not an overwrite.

Purpose: Closes CAP-01 (quick-save) and CAP-02 (add/edit) with the event-sourcing invariant intact. Builds directly on 02-02's schema/validation/appendStatusEventTx and 02-03's board page/card/lookups.
Output: `quickSaveApplication` + `updateApplication` domain writes, four Server Actions, three client dialogs, the change-stage trigger on the card, and the Add/Quick-Save buttons on the board page.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client dialog form → Server Action | Untrusted form input crosses into the mutation tier |
| Server Action → domain write → SQLite | Validated input persisted; stage changes must stay event-sourced |
| stored postingUrl → rendered href | A pasted URL could carry a `javascript:`/malformed scheme |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-12 | Tampering | quickSaveAction / updateApplicationAction input | high | mitigate | Every Server Action `safeParse`s against the Zod schema and returns the typed error copy on failure; the domain function `.parse()`s again (defense in depth) before any Drizzle write (ASVS V5). |
| T-02-13 | Tampering | postingUrl rendered as a clickable link | high | mitigate | postingUrl validated `z.string().url()` + http/https-only at the write boundary (02-02); rendered only as an escaped href after validation, never interpolated raw and never via a raw-HTML injection prop. |
| T-02-14 | Repudiation / Tampering | direct current-stage overwrite bypassing history | high | mitigate | No write path sets `currentStageId` directly; all stage changes append a dated status event via appendStatusEventTx and recompute (D-09) — enforced by the Task 1 grep + tests. |
| T-02-15 | Information Disclosure | client dialog importing the server-only db | medium | mitigate | Dialogs receive lookup data as props and mutate only through Server Actions; none imports `@/db/client` (enforced by the Task 3 negative grep). |
</threat_model>
